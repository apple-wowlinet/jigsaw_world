# 注册登录注意事项

本项目的登录和注册功能基于 Supabase Auth 实现，当前支持邮箱密码登录/注册和 Google 账号登录/注册。完成代码接入后，还需要在 Supabase 控制台和本地环境中确认以下配置。

## Supabase 控制台配置

1. 打开 Supabase 项目控制台。
2. 进入 `Authentication > Providers > Google`。
3. 启用 Google 登录 Provider。
4. 填入 Google Cloud Console 中创建的 OAuth Client ID 和 Client Secret。
5. 保存配置后，确认 Google Provider 状态为启用。

## URL Configuration

在 Supabase 控制台进入 `Authentication > URL Configuration`，确认以下配置：

1. `Site URL` 本地开发建议设置为：

```text
http://localhost:3000
```

2. `Redirect URLs` 本地开发至少添加：

```text
http://localhost:3000/auth/callback
```

3. 上线部署后，需要额外添加生产环境回调地址，例如：

```text
https://your-domain.com/auth/callback
```

## Google Cloud OAuth 配置

在 Google Cloud Console 创建 OAuth 客户端时，需要确认授权回调 URI 与 Supabase 要求一致。通常需要在 Google OAuth Client 的 Authorized redirect URIs 中添加 Supabase 提供的回调地址，格式类似：

```text
https://<your-project-ref>.supabase.co/auth/v1/callback
```

其中 `<your-project-ref>` 替换为当前 Supabase 项目的 ref。

## 邮箱注册确认

邮箱注册是否需要用户点击确认邮件，由 Supabase 的 Email Auth 配置决定：

1. 如果启用了邮箱确认，用户注册后会看到“请检查邮箱完成确认”的提示，需要点击邮件中的确认链接后才能登录。
2. 如果关闭邮箱确认，注册成功后 Supabase 可能会立即返回 session，页面会自动跳转到目标页面。
3. 当前代码已兼容以上两种模式。

## 环境变量

本地 `.env.local` 必须包含以下变量：

```env
NEXT_PUBLIC_SUPABASE_URL=<supabase-project-url>
NEXT_PUBLIC_SUPABASE_ANON_KEY=<supabase-anon-key>
```

这两个变量用于浏览器端 Supabase Auth。缺失时，应用会抛出 `Missing Supabase environment variables` 错误。

## 回调路由

当前认证回调页面为：

```text
/auth/callback
```

邮箱确认和 Google OAuth 登录都会回到该路由。该页面会完成 Supabase PKCE code exchange，并在成功后跳转回 `next` 指定的站内路径；如果没有指定 `next`，默认跳转到首页 `/`。

## 本地验证步骤

确认 Node.js 和 npm 可用后，在项目根目录执行：

```bash
npm run lint
npm run dev
```

然后依次测试：

1. 打开 `http://localhost:3000/register`，使用邮箱密码注册。
2. 如果启用了邮箱确认，检查邮箱并点击确认链接。
3. 打开 `http://localhost:3000/login`，使用邮箱密码登录。
4. 在 `/login` 或 `/register` 页面点击 Google 登录按钮，确认可以完成 OAuth 跳转并返回站点。
5. 登录成功后，确认 Header 中显示用户名称和 `Log out` 按钮。
6. 点击 `Log out`，确认 Header 恢复显示 `Login` 和 `Register`。

## 常见问题

1. Google 登录后没有回到站点：检查 Supabase `Redirect URLs` 是否包含当前环境的 `/auth/callback`。
2. Google 提示 redirect URI mismatch：检查 Google Cloud Console 中的 Authorized redirect URIs 是否包含 Supabase 的 `/auth/v1/callback` 地址。
3. 邮箱确认链接失效或跳转错误：检查 Supabase `Site URL` 和邮件模板中的确认链接配置。
4. 本地启动时报环境变量错误：检查 `.env.local` 是否存在并包含 Supabase URL 和 anon key。
5. 登录后 Header 没更新：刷新页面并检查浏览器控制台是否有 Supabase Auth 或环境变量错误。
